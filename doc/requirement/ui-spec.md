# MD2Word UI 规格

本文对应 **Desktop MVP 0.6.0**。同一套 React 页面通过 adapter 运行在两种后端：Electron 使用真实 Main/Worker 能力，普通浏览器使用 mock 预览。界面必须按运行时能力切换文案与控件，不能用浏览器演示结论代替桌面验收。

## 1. 设计目标

界面应像稳定、克制的 Windows 专业工具，而不是营销网页。用户在一个窗口内完成“选模板 -> 选 Markdown -> 选输出 -> 查看结果”，模板管理和排障作为次级页面存在。

- 界面语言：简体中文。
- 推荐窗口：1440x900；最低验收：1280x800。
- 信息密度：适中偏紧凑，重要状态始终可见，长日志在独立区域滚动。
- 图标：Lucide；图标配文字或可访问名称，不使用 emoji 充当功能图标。
- 状态：成功、警告、错误、运行中同时使用颜色、图标和文字表达。

### 1.1 运行模式标识

| 能力 | Electron 桌面运行 | 浏览器 mock |
|---|---|---|
| 文件与另存为 | Windows 原生对话框，Renderer 只持有 handle | 浏览器文件选择与模拟另存为 |
| 模板 | Main 隔离复制并由 Worker 校验 | localStorage 中的合成演示配置 |
| 转换/环境 | C# Worker、Word 与 Pandoc 真实结果 | 定时器与合成状态 |
| Mermaid | 本机 npx + Edge/Chrome 渲染 PNG/SVG；系统浏览器启动失败时可准备受管浏览器重试，按模式显示真实告警/错误 | 只演示阶段和状态，不宣称生成图片 |
| 能力说明 | 通过 Main 查询当前安装 Worker 的版本化清单 | 直接导入同一份受版本控制清单 |
| 输出操作 | 按 `jobId` 打开/定位真实结果 | 明确标注“模拟打开/定位” |

页头和侧栏必须持续显示“桌面版/桌面运行”或“原型/交互原型”。桌面 Worker 的兼容警告也必须显示，并准确区分已完成的正文随文图片缩小、内部链接 ASCII 安全书签重写和 admonition 固定背景/左线基础视觉，与仍待验收的丰富 admonition 布局、浮动/文本框/多栏/复杂表格单元格图片布局，不能因为它是真实转换就隐藏未迁移范围。

## 2. 全局框架

### 2.1 左侧导航

- 顶部：产品图标、`MD2Word`、副标题 `文档生成器`。
- 主导航：`生成 Word`、`模板管理`、`能力说明`、`环境与设置`。
- 当前项有背景、高亮图标和左侧/内侧强调标识；所有项目支持键盘聚焦。
- 底部按 adapter 显示 `desktop / APP` 或 `prototype / UI`；安全卡分别说明“真实路径只在 Main 与 Worker”或“当前不访问真实转换引擎”。

### 2.2 主内容区

- 页头包含页面标题、一句说明和与本页相关的主要操作。
- 卡片统一圆角、细边框和轻阴影；不要用多层渐变、过大标题或装饰性仪表盘。
- 主要按钮仅用于当前页面唯一主动作；危险操作使用红色弱按钮并二次确认。
- 页面高度不足时只滚动主内容；导航保持稳定。

## 3. 生成 Word 页面

### 3.1 布局

桌面宽度采用两列：

- 左侧主流程：固定高度的当前模板摘要、Markdown 文件、输出设置、生成按钮。
- 右侧上下文：模板摘要、任务进度/结果。
- 底部日志横跨可用区域，任务开始后保持可见。

1280x800 时允许卡片更紧凑并让日志内部滚动，但生成按钮、当前状态和取消按钮不能被推到不可见区域。模板库只在选择弹层内部滚动，不能随模板数量增长撑高主流程。

### 3.2 模板选择

- 默认态只显示当前模板的一条紧凑摘要和“更换模板”，摘要包含名称、默认标识、校验状态、DOCX 文件名和 CSS 类型；“管理模板”始终作为次级入口。
- 点击“更换模板”打开搜索弹层，支持按名称、用途、DOCX 文件名和 CSS 文件名过滤。当前模板优先显示，其余保持模板库顺序。
- 结果使用紧凑列表，最大高度约 360px 并内部滚动；模板再多也不改变生成页模板区域高度。搜索无结果时提供“清除搜索”。
- 右侧“当前配置”展示完整 DOCX/CSS 文件名、最近校验时间、能力和问题摘要，避免在左侧重复详细说明。
- 模板 `invalid` 时允许选中查看具体问题，但两个生成入口均禁用；`warning` 时可继续并明确显示警告。
- 转换运行中或“另存为”窗口打开时禁用“更换模板”；非运行状态切换模板时清除上一任务的日志与结果。
- 模板为空时显示空态和“前往模板管理”。

### 3.3 Markdown 文件

- 拖放区支持点击选择与文件拖入，明确接受 `.md` / `.markdown` 单文件。
- 空态文案：`拖入 Markdown，或点击选择文件`。
- 选中后显示文件图标、名称、大小与移除按钮；Electron 显示“已由桌面应用安全登记”，两种模式都不展示完整绝对路径。
- 非法类型、多个文件或不可读文件在拖放区附近显示错误，不用仅靠 toast。

### 3.4 输出与另存为

- 未开始时显示 `每次生成时选择保存位置`，不要求用户预先填写路径。
- Electron 点击主按钮后打开 Windows 原生“另存为”；浏览器 mock 打开含建议文件名、`.docx` 提示、取消和确认的模拟窗口。
- 取消后返回原状态，不新增日志、`jobId`、Worker 或临时目录。
- 确认后只向 Renderer 返回 output handle、文件名和脱敏展示信息，并进入排队/运行状态；真实路径保留在 Main。

### 3.5 任务状态

| 状态 | UI 行为 |
|---|---|
| idle | 主按钮可用需满足模板有效且已选择 Markdown；右侧显示准备提示。 |
| saving | 显示另存为窗口，底层主按钮不可重复点击。 |
| queued | 显示队列位置；可取消尚未开始的任务。 |
| running | 显示当前阶段、阶段型进度条、开始时间与“取消生成”。 |
| canceling | 按钮改为 `正在安全取消…` 并禁用，提示正在关闭 Word/清理临时文件。 |
| succeeded | 绿色结果卡，显示文件名及“打开文件”“在文件夹中显示”；浏览器 mock 按钮标注模拟。真实结果警告在成功卡中保留。 |
| failed | 红色结果卡，显示失败阶段、原因、建议操作和重试。 |
| canceled | 中性结果卡，说明未生成/未保留输出，可重新开始。 |

进度条只能表达已知阶段，不显示虚假的精确处理百分比。浏览器 mock 可用确定的模拟阶段推进，但文案必须含“演示”。

公开阶段顺序为：排队、准备、读取元数据、Pandoc、Mermaid/资源处理（存在 fenced Mermaid 且模式不是 `off` 时）、Word 导入、模板装配、Word 收口、Open XML 收口、清理。Mermaid 阶段表示本地渲染、相邻图注绑定和统一图号处理；页面不得为没有收到的阶段伪造精确百分比。

### 3.6 日志

- 每行显示时间、级别和消息；级别为 info、warning、error。
- 默认自动滚动到最新消息，用户向上滚动后暂时停止自动跟随。
- 提供清空或折叠；运行期间清空只影响显示，不影响任务。
- 不输出 Markdown 正文、模板内部文本、凭据或完整用户目录。

## 4. 模板管理页面

### 4.1 列表

- 页头主按钮：`添加模板`。
- 每张模板卡/每行展示名称、说明、DOCX、CSS、默认标识、校验状态、最近校验时间。
- 操作：`编辑`、`重新校验`、`设为默认`、`删除`。默认模板不显示无意义的“设为默认”。
- 浏览器 mock 的初始数据：
  - 使用说明书：默认、内置 CSS、校验通过。
  - 技术报告：自定义 CSS、校验通过；可通过演示入口切换成警告/错误状态。
- 开发态 Electron 模板库首次启动为空，用户通过“添加模板”导入的 DOCX/CSS 写入 `templates/user`。Windows 基线从 EXE 同级 `templates/*/index.json` 加载源码中审核通过的公开模板包，当前 `reference/index.json` 提供“公开参考模板”；使用自定义模板时把仓库外完整私有模板包直接复制为任意 `templates/<package-name>`，应用遍历各子目录索引并合并显示。仓库和构建上下文不捆绑真实模板。

### 4.2 添加/编辑窗口

窗口固定在应用视口根层，不受主内容滚动区或页面入场动画影响。标题、表单和底部操作分为三段；窗口高度不超过当前视口，空间不足时只让中间表单区滚动，标题、关闭按钮和底部操作始终可见。

字段顺序：

1. 模板名称（必填，唯一）。
2. 说明（可选）。
3. Word 模板 `.docx`（必填）。
4. CSS 模式：内置默认 / 自定义。
5. 自定义 `.css`（选择自定义时必填）。
6. Mermaid 默认模式（auto / off / required）与格式（png / svg）。

窗口底部先展示校验结果，再允许保存。校验项包括文件可读、正文书签、可选书签、CSS 显式样式映射和 Word 原生回退；映射详情必须分别展示正文、`1.` 有序列表、`-` 无序列表、H1-H6、图题、表题、代码块、行内代码、表格、admonition 和图片段的目标样式，并用“CSS 已解析”或“Word 原生”标明来源。CSS 显式样式先按 style ID、名称或 alias 精确解析；精确候选不存在时才按 Word 内建样式中英文等价名解析，例如 `正文` 可解析到 `Normal`，而 `正文1` 不视为同名。CSS 显式引用样式缺失/歧义时为 `invalid`；CSS 未映射且模板缺少某级标题原生样式时显示条件性 `warning`，说明只有源文档经 `heading_base_level` 重映射后实际使用该级别才会在转换阶段被阻止。带 `capabilityId` 的问题显示“查看对应能力”，点击后关闭窗口并聚焦能力页对应条目。`warning` 第一次点击提示检查，第二次使用“确认警告并保存”。

Mermaid 选项说明必须明确：`off` 保留代码；`auto` 单图失败会保留对应代码并在成功结果中显示警告；`required` 任一图失败都会终止任务。格式说明只承诺通过安全校验的 PNG/SVG。Markdown 图注写法为紧随 Mermaid fenced 代码块的 `<!-- caption: 标题 -->`，历史 `cation` 仅作兼容；中间出现任何非空白节点即不绑定。成功图注经 CSS 映射到模板 Caption/“图注”等既有样式，并与普通图片共用按章图号。

浏览器 mock 文件选择只保存文件名和 mock handle，不读取 DOCX 内容。Electron 由 Main 执行原生选择、隔离复制和 Worker 校验，Renderer 不持有源路径。

### 4.3 删除与默认模板

- 删除需要确认；Electron 明确“只删除应用管理副本，不删除用户原文件”，浏览器明确“只删除演示配置”。
- 删除默认模板后，界面按需求自动选择下一个有效模板；无有效模板则生成页进入空态。
- 设置默认后列表与生成页立即同步，刷新后仍保留。

## 5. 能力说明页面

### 5.1 页头与摘要

- 页头说明该清单随版本发布，右侧显示产品版本、清单 schema 和 Worker 协议版本。
- 四张摘要卡显示转换能力条目、已实现能力、Front Matter 键和已声明边界数量。
- 状态不能只靠颜色，统一显示“支持”“条件支持”“有限支持”“未承诺”。

### 5.2 分类与搜索

- `语法与转换`：按 Markdown、模板和 Word 成品类别展示能力 ID、摘要、细节、示例及相关元数据。
- `Front Matter`：以卡片展示键、类型、默认行为、允许值、模板要求和 YAML 示例；搜索覆盖键、ID、说明、默认值和示例。
- `模板契约`：分别展示必需/按需书签、全部 CSS 语义角色和校验约定。
- `边界与环境`：展示明确限制、Windows/Word/Pandoc/.NET 要求，以及固定 Mermaid 工具版本。
- 搜索无结果时显示本地空态，不隐藏页头版本和摘要。切换类别时清除深链高亮，但不改能力数据。

### 5.3 数据与错误状态

- Electron 页面只调用 `capabilities.describe()`，不直接读取 JSON 或文件路径；Main 缓存 Worker 的已校验结果。
- 浏览器 mock 导入同一 `resources/conversion/capabilities.json`，首屏无需等待异步请求。
- Worker/IPC 查询失败时显示可行动错误和“重新读取”，其他三个页面仍可使用。
- 从模板问题深链时自动切到对应类别、滚动居中、聚焦并以可见焦点环高亮条目。

## 6. 环境与设置页面

- 0.6.0 的模板库提示同时说明“便携版使用 EXE 同级 templates；安装版使用用户数据目录”，打开目录仍通过同一个无参数 Main 接口完成。安装版首次启动可见公开参考模板，导入和编辑交互不变。

- 环境卡：Windows、Microsoft Word、Pandoc、C# Worker、Mermaid。
- 每张卡显示状态、版本或路径摘要、必要性以及一条解释。
- Word/Pandoc/Worker 缺失为阻塞；Mermaid 可用需同时检测到 npx 和本机 Microsoft Edge 或 Google Chrome，缺失默认是可选警告，模板选择 `required` 时阻止生成。
- Mermaid 卡说明固定使用 `@mermaid-js/mermaid-cli@11.16.0`、`puppeteer@25.3.0` 和本地浏览器；首次使用可能由 npx 获取固定工具包，系统浏览器启动失败时还可能获取受管 `chrome-headless-shell` 到应用私有缓存，但文档内容不会上传。不得向普通用户展示 npm stderr、图源正文或私人绝对路径。
- `重新检测` 在 Electron 中调用真实环境检查，在浏览器中刷新合成状态，并显示检查时间。
- Electron 模板库区说明 Portable 发布版位于 `MD2Word.exe` 同级 `templates`、当前目录由 Main 管理，并提供受控打开目录；开发运行与 Setup 安装版实际落到 `userData/templates`，浏览器只说明 localStorage，不伪造可打开路径。
- `重置演示数据` 只在浏览器 mock 出现，确认后恢复两个初始模板和默认环境状态；桌面运行不提供一键删除真实模板的伪“重置”。

## 7. 反馈与文案规则

- 内置演示配置、合成夹具与能力示例统一使用“示例 正文”“示例 有序列项”等中性名称；用户实际导入的模板仍按其 DOCX/CSS 原始名称展示和解析，不做重命名或名称限制。

- 优先在触发控件附近显示验证问题；toast 只用于短暂成功反馈或跨页结果。
- 错误文案结构：发生了什么 + 哪一步失败 + 用户下一步。
- 环境或模板问题使用具体名称，例如 `缺少正文结束书签 MANUAL_BODY_END`，不只写“校验失败”。
- Mermaid `auto` 失败以“对应图已保留为代码 + 稳定错误码”说明；`required` 失败同时指出缺少 npx/浏览器、浏览器启动/受管安装失败、安装或渲染超时、输入越限、输出安全校验等可行动原因，不显示图源或外部工具原始 stderr。
- `IMAGE_SIZE_FINALIZATION_FAILED` 只在正文图片确实超过可用版心 1pt 且 Word 缩放后仍无法落入相同容差时显示；不得因 COM 浮点误差对已经贴合版心的图片误报。
- 浏览器 mock 统一使用 `模拟`、`演示` 标签；Electron 真实动作不加模拟标签，但必须保留 Worker 返回的兼容警告和能力边界说明。
- 文件路径过长时保留文件名和末尾目录，悬停/聚焦可查看完整路径；日志默认脱敏用户目录。

## 8. 可访问性与交互细节

- Tab 顺序与视觉顺序一致；弹窗打开后焦点进入弹窗，关闭后回到触发按钮。
- 弹窗内的跨页入口关闭弹窗并完成导航后，焦点进入新页面主标题，不能落到页面主体或已卸载控件。
- Escape 关闭非破坏性弹窗；运行中的取消必须点击明确按钮，不用 Escape 触发。
- 模板弹层打开后焦点进入搜索框；方向键可移动结果，Home/End 跳转首尾，Enter 选择，Escape 关闭。搜索结果数通过 `aria-live` 适度播报。
- 所有表单控件有 label、错误描述关联和可见焦点环。
- 对比度满足常见桌面阅读需要；禁用态不能仅通过降低到难以阅读的透明度表达。
- 动画尊重 `prefers-reduced-motion`；进度与状态变化使用 `aria-live` 适度播报。

## 9. 视觉验收矩阵

| 尺寸 | 页面/状态 | 重点 |
|---|---|---|
| 1440x900 | 四个主页面 | 信息层级、两列布局、卡片密度、日志可读性 |
| 1280x800 | 生成 Word | 主按钮、状态、取消、日志均可达，无横向滚动 |
| 1440x900 / 1280x800 | 模板选择弹层/多模板 | 弹层不被裁切；搜索、长列表内部滚动、校验状态、键盘选择和无结果反馈可用 |
| 1440x900 | 添加/编辑模板 | 字段、校验问题与底部操作不被裁切 |
| 1440x900 | 成功/失败/取消 | 颜色以外仍有明确文字和图标 |
